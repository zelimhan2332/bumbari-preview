## Стадия продукта

Проект — браузерный конструктор выкроек Bumbari на основе методики «Мюллер и сын». В `preview/` есть текущие построения, моделирование, манекен, сохранение проекта и экспорт. Не считай весь каталог или каждую мерку готовой производственной выкройкой: точные статусы проверяй в `IMPLEMENTATION.md` и профильных обзорах.

Для PDF проверь печать в масштабе 100% и квадрат 100 × 100 мм; до раскроя нужен макет. Программные тесты не заменяют визуальную проверку страниц книги и примерку.

## Навигация по знаниям

- Навык: `skills/mueller-patternmaking/SKILL.md`.
- Сборник «Ателье — 2001»: `skills/mueller-patternmaking/references/atelier-2001.md`.
- Сборник «Ателье — 2004»: `skills/mueller-patternmaking/references/atelier-2004.md`.
- Реестр: `skills/mueller-patternmaking/references/library.json`.
- Покрытие и границы проверки: `skills/mueller-patternmaking/references/coverage.md`.
- Перечень источников: `docs/SOURCES.md`; этапы изучения: `docs/STUDY.md`.
- Поиск и проверка локальных книг: `skills/mueller-patternmaking/scripts/library.py`.

PDF, полный OCR и изображения страниц не включать в репозиторий. Для локальной библиотеки задавай `MUELLER_LIBRARY_ROOT`, для OCR-кэша — `MUELLER_OCR_CACHE`; b10 можно указать переменной `MUELLER_BOOK_B10`. Реестр намеренно не содержит абсолютных путей к компьютеру владельца.

Перед реализацией алгоритма прочитай нужную главу в конкретном издании, визуально сверь текст и чертёж, укажи страницы и контрольный пример. Не выдавай OCR или оглавление за изученную конструкцию. Разделяй книжное правило и экспериментальное инженерное решение.

## Работа с GitHub

1. Перед началом проверь `git fetch origin`, ветку и чистоту рабочего дерева.
2. Создай отдельную рабочую ветку от актуального `test`; PR направляй в `test`.
3. Проверь затронутые тесты и `git diff --check`; перед слиянием дождись GitHub Actions.
4. Не меняй напрямую `test`, адрес сайта или настройки Pages.
5. Не коммить PDF, OCR, личные мерки, фото клиентов, ключи, секреты и абсолютные локальные пути.
