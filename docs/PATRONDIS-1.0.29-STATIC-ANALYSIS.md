# Patrondis 1.0.29 — статический разбор логики лекал

Дата: 18.11.2026. Анализ основного APK `com.patronfy.patrondiss.apk`, SHA-256 `f269f2e633592e25cc5add15b42b228b88535916f33b6cda9598f652a41d39e5`, JADX через REA 0.7.1. APK не запускался, покупка и обход оплаты не предпринимались.

## Что делает приложение по коду

1. Старт проходит через Splash и предварительный экран авторизации. MainActivity строит категории лекал и платёжный экран/состояние подписки. Экранные компоненты: блуза, брюки, рукав, прочие мерки, каталог GridActivity и экран выбранного изделия.
2. Форма брюк принимает 5 величин: талия, бёдра, высота бёдер, длина юбки и длина брюк. При выборе поля меняется поясняющая схема. Диапазоны в обработчике: талия 58–150 см, бёдра 70–150, высота бёдер 15–32, юбка 40–70, брюки 80–140. Дополнительно рассчитывается разность полуобхватов `((hip+1)/2)-((waist+1)/2)` и допускается 0–15. Эти пределы и прибавка — наблюдение декомпилированного кода, не подтверждение портновской методики.
3. Каталог локальный: 7 моделей верхней одежды, 9 нижней, 3 рукава, 4 прочие. Имена каталога включают базу лифа с двумя вытачками, варианты основы/платья, короткую кимоно, бюстье, трикотажную футболку, толстовку, прямую/круговую/сегментную юбку, три вида брюк, три рукава и три воротника плюс капюшон.
4. В `GridActivity.j()` видны вычислительные ветки для юбок. Для полукруглой юбки используется приближение `waist/3.14`, для полной окружности — `waist/6.28` плюс длина. Для 4/6/8 полотнищ делятся скорректированные обхваты и применяются геометрические вычисления. Базовая юбка распределяет раствор вытачек через значения обхватов с поправкой +1. Декомпилированный метод содержит сложные ветвления; переносить формулы без проверки контрольными примерами нельзя.
5. После выбора модели приложение собирает отдельные фрагменты для переда и спинки. Для рисунка есть ImageView, а буквы (a, b, c …) отображаются отдельными текстовыми полями в сантиметрах. Шаговые экраны — отдельные фрагменты `u1.a…u1.s`: код выбирает разные ресурсы `n00…n17` по типу модели и подставляет рассчитанные значения. По ресурсам и строкам подтверждены шаги 1–16 и итоговый экран; для одной модели шаги/ресурсы могут отличаться, поэтому это не одна универсальная инструкция.
6. Инструкции раскроя предупреждают, что рисунок служит ориентиром, лекала меняются по меркам и припуски не включены; упоминается раскрой ткани в сложенном виде и 4 шага раскроя.

## Что полезно для нашей программы

- Сохранить понятный маршрут: мерки → выбор фасона → отдельные перед/спинка → измеренные точки на схеме → шаги построения → проверка и печать.
- При фокусе на поле показывать, где снять соответствующую мерку.
- Не делать единый «умный» экран: разделить экран построения на изображение, обозначения размеров и короткий текст шага.
- Заложить проверки границ, подсказки о единицах, проверку контрольных примеров и видимую маркировку схемы как черновика до проверки.
- Использовать свои рисунки, тексты и проверенные формулы; не копировать проприетарные картинки/тексты Patrondis.

## Дополнение: брюки, связь мерок и генератора

В smali-распаковке подтверждена цепочка формы брюк. Поля формы связаны с измерениями так: q = P001 обхват талии, r = P002 обхват бёдер, s = P003 высота бёдер, t = P004 длина юбки, u = P005 длина брюк. Это видно по порядку EditText в `activity_medida_pantalon`, binding `q1.d` и сохранению значений обработчиком `m1.j.onClick`. Метод `GridActivity.j()` выбирает ветку по enum-модели (`s1.b`): q = `PANTALON_VERANIEGO`, r = `PANTALON_DEPORTIVO`, s = `PANTALON_FORMAL`.

- **Летние брюки:** ветка использует r (обхват бёдер) и u (длина брюк). Видимые промежуточные параметры: B = (r + 7) / 2; C = u; D = B / 2; E = r / 3 + 3; G = 2r/16 − 1; F = G/2; H = F − 2. Также в выход записаны постоянные 1, 9 и 4. Деления проходят через округление до десятых. Это внутренние буквенные точки чертежа; их геометрический смысл по коду полностью не назван.
- **Спортивные брюки:** ветка обращается к r (бёдра), s (высота бёдер) и u (длина брюк), строит набор величин B–M и a0–e0. Внутри есть степени, квадратные корни и тангенс. q (талия) и t (длина юбки) в этой ветке напрямую не читаются.
- **Формальные брюки:** ветка использует q, r, s, t и u; вычислений заметно больше (включая квадратные корни и тангенс), выход включает буквы A–Q и a0–i0. Переписывать это как достоверную методику по одним smali-регистрам нельзя: сначала надо связать каждую букву с конкретным отрезком схемы и проверить контрольными расчётами.

Общий валидатор всё равно требует заполнить все пять полей и проверяет их диапазоны: талия 58–150 см, бёдра 70–150, высота бёдер 15–32, длина юбки 40–70, длина брюк 80–140. Затем сравнивает полуобхваты бёдер и талии с поправкой +1. Поэтому проверка формы общая, а входы конкретной модели отличаются. Ограничения — наблюдаемая логика APK, не рекомендация по снятию мерок и не проверенная посадка.

Техническая база: `MedidaPantalonActivity.smali`, `m1/j.smali` (обработчик формы), `GridActivity.smali` (`j()V`, расчёт по типу), enum `s1/b.smali`, ресурс `activity_medida_pantalon.xml`; Apktool 3.0.3, smali-декомпиляция. JADX в этом продолжении не стартовал; формулы сверялись непосредственно по Smali и таблице ресурсов.
