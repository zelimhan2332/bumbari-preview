# Bumbari Android MVP

Нативный Kotlin/Jetpack Compose модуль, не WebView. Веб-код preview/ не изменён.
Основа исследования: test@1b02bee; четырёхклинная модель дополнительно изучена
в origin/feat/four-gore-skirt (не слита автоматически в веб-публикацию).

## Сборка

JDK17, Android SDK36, Gradle8.11.1. Из android/: `gradlew assembleDebug testDebugUnitTest`.
SDK задаётся ANDROID_HOME либо локальным local.properties (не коммитить).
APK: app/build/outputs/apk/debug/app-debug.apk. Debug-подпись только для тестирования.
Интернет используется только по нажатию «Проверить обновления» для получения
публичного GitHub Release. Мерки и проекты никуда не отправляются; аналитики
и платных сервисов нет.

Compose/Activity — новые необходимые зависимости для прямо выбранной владельцем
нативной технологии. org.json в приложении — Android SDK, внешняя реализация
подключена только для JVM-тестов; JUnit также только тестовый.

## Архитектура и данные

- Project.kt: отдельный тип модели, ID, версия алгоритма, мерки/настройки/заметки,
  строгий JSON с единицами cm. Версия 2 добавляет прямую юбку; файлы версии 1
  для полусолнца, солнца и клиньев остаются доступны.
- Geometry.kt: параметрические точки в сантиметрах, отдельные срезы и линии швов.
- PatternPdf.kt: Android PdfDocument/Canvas, векторные линии, мм→72/25.4 pt,
  A4/A0 с полями10мм, нахлёстом10мм, номерами R/C. Каждая деталь отдельной серией.
  Контрольный квадрат100мм — отдельная страница, не разрезается плитками.
- MainActivity.kt: каталог юбок, пустые пользовательские мерки (без выдуманных
  размеров), форма с запятой/точкой, чертёж, локальные проекты, SAF JSON/PDF.
  Каждый проект — отдельный файл во внутреннем каталоге приложения; модель
  и алгоритм сохраняются. Автобэкап отключён, синхронизации нет.
- AppUpdate.kt: проверка последнего GitHub Release, контроль версии/пакета/URL,
  загрузка APK с проверкой SHA-256 и открытие системного установщика Android.

## Источники и инженерные решения

Полусолнце/солнце перенесены из preview/half-circle-kit.js и описаны в
docs/HALF-CIRCLE-SKIRT.md, docs/FULL-CIRCLE-SKIRT.md. Радиус = (От+прибавка)/π
или /(2π). Это аналитическая геометрия для согласования пояса, НЕ буквальная
формула Мюллера. Свадебный вариант b07 PDF170–172 (От/6−1) не подменяется
этим решением; конструкция без его поправки и модельной раздвижки.

Четыре одинаковых клина: четверти талии/бёдер, smoothstep-переход ширины,
расширение на сторону. Опора b10 PDF5–8, но одинаковые перед/спинка и
интерполяция — инженерное упрощение, не книжная четырёхклинная основа.
В отличие от старой веб-ветки припуск рассчитан нормальным смещением
отрезков с пересечением соседних линий, а не прибавкой только по X.
Версия Android алгоритма отдельная, не заявляется побитовый паритет с JS.

Пояс: b10 PDF9/печатная10 рис9, готовая ширина2–5см, выступ3см. Общий принцип
припусков и знаков: b10 PDF16/печатная17 рис29. Настройки прибавок, молнии,
подгибки — выбор пользователя в пределах прототипа, не универсальные числа книги.

Прямая юбка добавлена в каталог. Книжная опора: «Ателье—2001» PDF5–7
(печатные6–8): сетка, прибавка по бёдрам 1–2см на половину изделия, общий
раствор и два контрольных распределения 12=7+2+3 и 14=7+2+3+2см. Android
строит перед на сгибе, спинку зеркальной парой, пояс и шлицу. Кривые бокового
среза, настройка вытачек для мерок вне этих двух примеров, припуски и цифровой
контур — инженерная аппроксимация; нужна проверка бумажным пробником и примеркой.
Подробности: docs/ANDROID-STRAIGHT-SKIRT.md.

## Ограничения

Только тканая модель без подкладки, без индивидуального баланса и асимметрии.
Не производственно проверенные лекала. Перед экспортом требуется подтверждение
макета; физическая печать и примерка отдельно. Круговую юбку отвесить и
выровнять низ. Неподдерживаемые данные блокируются, не исправляются молча.
Нет проверки раскладки на ткани, облака, других категорий и автоматической
миграции будущих версий алгоритма. Неподдерживаемые версии JSON отклоняются.

Приложение установлено и запущено на подключённом телефоне; каталог и форму
прямой юбки проверили снимком экрана. Android PDF и сохранение/импорт проектов
на устройстве ещё не проверяли; контроль печати100мм и примерка также не выполнены.

## Проверка этой итерации

Локально assembleDebug и testDebugUnitTest: BUILD SUCCESSFUL, семь JVM-тестов,
0 ошибок. Проверены четыре модели, JSON round trip, запятая/точка, границы,
размеры припусков и плиточное покрытие. 100мм переводятся в283,464566929pt.
Это проверка коэффициента/геометрии, НЕ измерение реально созданного Android PDF.
Телефон Xiaomi подключён: APK установлен и открыт. Снимком экрана подтверждены
карточка прямой юбки и форма мерок. SAF-сценарии и отрисовка Android PDF на
устройстве пока не проверены.

## Обновления без кабеля

Приложение умеет проверять GitHub Releases и передавать подписанный APK
установщику Android. Workflow `.github/workflows/android-release.yml` создаёт
APK и `update.json` при публикации тега `android-v*`. Перед первым таким
выпуском нужно настроить четыре Actions secrets из `docs/ANDROID-UPDATES.md`.
Установленные сейчас debug-сборки подписаны отладочным ключом и не обновятся
release-APK; требуется один раз установить release-подписанную версию. Дальше
обновления проверяются на телефоне без подключения кабеля, но пользователь
подтверждает установку в системном окне Android.
Веб-файлы сохранены без изменений. Новые формулы книги не заявлены проверенными:
переиспользованы явно документированные инженерные конструкции проекта.
